# iOS 1.1.2 TestFlight Release Design

## Goal

Produce a signed App Store Connect IPA for Granite `1.1.2+25` that includes the current uncommitted `1.1.1+24` mobile work, the backward-compatible Kakao Account login change, and an iOS minimum deployment target of 15.0.

The output is an IPA ready for the user to upload to TestFlight. This task does not upload the artifact to App Store Connect.

## Release Baseline

The release baseline is the current `version/1.0.0` working tree at commit `ca95fcb`, including its reviewed uncommitted changes. Those changes currently pass formatting, static analysis, and all 100 Flutter tests.

The uncommitted baseline contains four logical groups:

1. Android Apple web authentication callback and state validation hardening.
2. iOS WebView bottom safe-area behavior, iOS edge-swipe history, and Android back invocation support.
3. Android App Bundle support in `tool/flutter_granite.sh` and its regression test.
4. The recorded production version `1.1.1+24` and the two existing WebView implementation-plan documents.

No baseline change is discarded or reconstructed from memory.

## Commit Strategy

The current working tree is committed in reviewable functional groups before the Kakao branch is integrated. Partial staging is used where one file contains changes for more than one group, especially `AndroidManifest.xml` and `pubspec.yaml`.

The intended history is:

1. Apple Android callback hardening.
2. WebView navigation and safe-area improvements, including the direct WKWebView dependency and implementation-plan documents.
3. Android App Bundle build-wrapper support.
4. The remaining `1.1.1+24` version record.
5. Merge of `feat/kakao-account-login-app`, preserving its three existing commits.
6. A release commit that sets `1.1.2+25` and raises the iOS deployment target to 15.0.

Every source change present before this release task remains represented in Git history.

## Kakao Login Integration

The existing feature branch `feat/kakao-account-login-app` is merged after the current working tree is committed. Its changes are isolated to the native-auth request model, Flutter bridge handler, Kakao login service, and their tests, so they do not overlap the current baseline edits.

The merged behavior is:

- A new app recognizes the web bridge hint `loginMode: "account"` for Kakao.
- It opens Kakao's official account login surface with a forced login prompt.
- Missing, unsupported, or malformed login modes keep the prior KakaoTalk-preferred behavior.
- Closing the iOS Kakao account sheet is treated as cancellation rather than a generic failure.

The already-deployed web remains compatible with older app versions because their bridge handlers ignore the extra payload field.

## Version and Minimum iOS Settings

The Flutter package version becomes:

```yaml
version: 1.1.2+25
```

The iOS deployment target becomes 15.0 in every source-controlled setting that determines the archived application's `MinimumOSVersion`:

- `ios/Podfile`: `platform :ios, '15.0'`
- `ios/Runner.xcodeproj/project.pbxproj`: every `IPHONEOS_DEPLOYMENT_TARGET` entry is `15.0`

The Podfile comment is updated so it describes the Granite release policy rather than the older Kakao SDK minimum.

The change intentionally drops support for iOS 13 and iOS 14. It resolves App Store Connect warning 90068 before Apple's Spring 2027 enforcement.

## Regression Coverage

Source-level tests verify both release properties before an archive is built:

- `pubspec.yaml` contains `version: 1.1.2+25`.
- `ios/Podfile` declares iOS 15.0.
- Every checked-in Xcode deployment target is 15.0 and no 13.0 deployment target remains.

Existing Kakao bridge and login-service tests continue to verify account mode, legacy defaults, and cancellation mapping.

The pre-archive gate is:

```text
dart format --output=none --set-exit-if-changed lib test
flutter analyze
flutter test
git diff --check
```

## IPA Build and Validation

The production wrapper builds the archive and exports it with the existing manual App Store Connect configuration:

```text
tool/flutter_granite.sh build ipa --env prod
```

The build uses the installed Apple Distribution identity for team `JSC5N5XFCM` and the existing App Store Connect provisioning profile mapped to `com.granite.climbing`.

After export, the IPA is inspected rather than accepted solely from the command exit code. The embedded Runner `Info.plist` must report:

- `CFBundleIdentifier`: `com.granite.climbing`
- `CFBundleShortVersionString`: `1.1.2`
- `CFBundleVersion`: `25`
- `MinimumOSVersion`: `15.0`

The artifact path and validation results are returned to the user. Uploading to TestFlight remains a separate user-controlled step.

## Failure Handling

- If a logical baseline commit cannot be staged without unrelated changes, stop and inspect the staged diff before committing.
- If the Kakao merge conflicts, abort the merge and resolve from the two known working branches without discarding either side.
- If tests or analysis fail, do not archive until the root cause is fixed and the complete gate passes again.
- If archive signing or export fails, preserve the source commits and report the exact certificate or provisioning-profile failure. Do not change the bundle identifier or signing team as a workaround.
- If exported metadata differs from `1.1.2+25` or iOS 15.0, reject that IPA and correct the source build settings before rebuilding.

## Out of Scope

- Uploading the IPA to App Store Connect or TestFlight.
- Changing the app bundle identifier, Apple development team, or Kakao application registration.
- Database, web, Android release-version, or production-web changes.
- Refactoring unrelated authentication or WebView code.
